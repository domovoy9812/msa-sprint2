### <a name="_qmphm5d6rvi3"></a>**Решение**
[Целевая архитектура](target_arch.puml)

|                                                                                                       **проблема**                                                                                                        | **Решение**                                                                                                                                                                                             |
|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------:|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|                                                                                                           NFR-1                                                                                                           | Разбиение монолита на микросервисы согласно диаграмме, в k8s кластере                                                                                                                                   |
|                                                                                                           NFR-2                                                                                                           | использование Istio в связке со стандартными инструментами k8s                                                                                                                                          |
|                                                                                                           NFR-3                                                                                                           | Развертывание kafka в многонодовой конфигурации в k8s                                                                                                                                                   |
|                                                                                                           NFR-4                                                                                                           | Jaeger, Prometheus, Grafana                                                                                                                                                                             |
|                                                                                                           NFR-5                                                                                                           | Реализация GraphQL сервиса                                                                                                                                                                              |
|                                                                 Сложность сопровождения, Невозможность гибкой разработки, Сложности с запуском новых фич                                                                  | Разбиение монолита на микросервисы с ограниченным функционалом, понятным API, поддержка автотестов, включая контрактные                                                                                 |
|                                                                                                  Низкая масштабируемость                                                                                                  | Разбиение монолита на микросервисы + стандартные механизмы масштабирования k8s                                                                                                                          |
| Плохо спроектированный REST API:<br/> - много методов для получения отдельных свойств сущностей. Такой API сложно поддерживать, при изменении модели придется переписывать API<br/> - DTO смешаны с домменными сущностями | Везде, где возможно в REST API, перейти к CRUD API, отделить DTO от сущностей в репозиториях                                                                                                            |
|                                                             Тесты не автоматизированы, используют самописные скрипты, вместо специализированных инструментов                                                              | Переписать тесты с использованием AT фреймворка, с автоматическим развертыванием тестового окружения, применением тестовых данных, выполнения тестов и публикации результатов, очисткой тестовых данных |
|                                                                                      Review и Hotel сервисы работают с одним доменом                                                                                      | При разбиении монолита на микросервисы, объединить эти сервисы в 1 микросервис                                                                                                                          |

### План разбиаения монолита на микросервисы

|                                         **Шаг**                                          | **Описание**                                                                                                                         |
|:----------------------------------------------------------------------------------------:|:-------------------------------------------------------------------------------------------------------------------------------------|
|            Вынести User Service, Promo Code Service в отдельные микросервисы             | Максимально просто устроены, не зависят от других сервисов                                                                           |
|        Объединить Hotel Service, Review Service и вынести в отдельный микросервис        | Нужно объединять несколько существующих сервисов, зависит от User Service                                                            |
|                     Вынести Booking Service в отдельный микросервис                      | Наиболее критичный с точки зрения бизнеса сервис, зависит от всех остальных сервисов, стоит выносить из монолита в последнюю очередь |
|                 Реалзиация API Gateway, GraphQl сервиса, микрофронтендов                 |                                                                                                                                      |
| Перенос решения в K8s, подключение Istio, настройка мониторинга, масштабирования/rollout |                                                                                                                                      |
